## [0.9.0] – 2026-11-12 – Reliability & Security Hardening

> The fixes from the v0.8.0 review (#222–#250). Hardens Harux against what it receives and who talks to it: no MLLP frame is lost silently any more (every frame is stored and answered, shutdown waits for frames in flight), the web UI refuses requests made by other sites, `store.max_memory_mb` now bounds real memory instead of an estimate a tenth of it, and the diff and validation no longer report correct or different messages wrongly.

### Upgrade Notes
- **Harux no longer starts with an invalid `harux.toml`.** Unknown keys (e.g. the `max_size_mb` logging key removed in 0.5) and out-of-range values were silently ignored before; check the error message on the first start after the update. (#233)
- **The store now holds fewer messages for the same `store.max_memory_mb`**, because it counts what they really cost. With ordinary ADT traffic the 512 MB default fits roughly 37,000 messages, so the 10,000-message count limit still applies first; deployments that raised `store.max_messages` and relied on the byte limit now get the memory they configured. (#226)
- **Stricter DT/TS validation can add `INVALID_DATATYPE` warnings to traffic that was clean before.** Timestamps must now have 4/6/8/10/12/14 digits, a fraction of 1–4 digits only after the seconds and an offset of exactly `+/-HHMM` on at least a full date; dates must exist. Senders that emit e.g. `+05`, a 5-digit fraction or `2024+0100` will show the warning after the update. This changes only the validation badge: such messages are still stored and ACK'd as before. Check the message list after deploying. (#238)
- **Daily log files are now pruned: only the last 14 are kept** (`logging.max_files`, today's file included). Before, they were never deleted. Set `max_files = 0` to keep all of them, e.g. if another tool archives the directory. Only files named exactly `<file>.YYYY-MM-DD` are ever deleted. A `max_files` key left over from before 0.5 is accepted again with this meaning. (#240)
- If users open the UI by DNS name (e.g. `http://harux.klinik.local:8080`), add that name to `server.allowed_hosts` in `harux.toml`; otherwise the browser gets `403 Host not allowed`. IP addresses and `localhost` always work. (#227)
- **ACK/NACK wire changes** (#218, #223, #266):
  - A NACK now carries `Message parse error: <reason>` in MSA-3, cut to 80 characters, **and** an ERR segment (ERR-3 `100` or `207` from HL7 table 0357, ERR-4 `E`, ERR-8 the reason). Before, MSA-3 was a fixed `Message parse error` and there was no ERR.
  - A frame above `mllp.max_message_size_mb` is answered with `AR` and the connection stays open. Before, the connection was closed without a reply.
  - Replies are encoded in the sender's charset and declare its MSH-18. Before, they were always UTF-8 without MSH-18.
  - A message is stored before its ACK is written.
  - Receivers that parse NACKs strictly, or expect UTF-8 replies from a Latin-1 interface, should be checked.
- **A letter or digit as an HL7 delimiter is now a parse error** and gets a NACK instead of an ACK. Only senders that negotiated such delimiters are affected. (#243)
- **`GET /api/export` returns the bytes as received.** A Latin-1 message is exported in Latin-1 (not converted to UTF-8), and the final segment terminator is kept. Tools that read the export as UTF-8 text should be checked. (#230)
- **`GET /api/search` uses the UI filter's semantics** (`has:warnings`/`has:errors`, tags, Unicode case folding), so a REST client can get different hits than before. New query parameters: `before=` on `/api/messages` and `/api/search`, `include_bookmarks=` on `/api/messages`. `before` combined with `offset` or `include_bookmarks` gives `400`. (#197, #198, #231)
- **New optional configuration keys:** `server.mllp_bind`, `server.web_bind`, `server.allowed_hosts`, `logging.max_files`. All of them are listed in `examples/harux-example.toml`. Only `logging.max_files` changes behaviour by default (see above).
- **Dependencies updated:** `toml` 0.8 → 1.2, `tower` 0.4 → 0.5, plus minor/patch updates of axum, serde, chrono, uuid, encoding_rs and others (Dependabot, #262–#264). No behaviour change is expected.

### Security
- **tokio 1.54.1 and anyhow 1.0.104** — `cargo audit` flagged tokio 1.49.0 (RUSTSEC-2026-0386, `AsyncFd` constructors violate I/O safety) and anyhow 1.0.102 (RUSTSEC-2026-0190, `Error::downcast_mut`) as unsound. Harux calls neither API; both are semver-compatible updates (`cargo update -p tokio -p anyhow`). The remaining warning, `pin-utils` (unmaintained, via hyper), has no fixed release and is ignored with a reason in `.cargo/audit.toml`. (#244)
- **The listeners' bind addresses are configurable** — both listeners always bound `0.0.0.0`, so network placement, the only access control Harux has, could not be set in Harux itself (#237). New `server.mllp_bind` and `server.web_bind` (default `0.0.0.0`, unchanged behaviour) take an IPv4 or IPv6 address: `127.0.0.1` keeps the web UI on this machine behind a reverse proxy that adds TLS and login, an interface address restricts a listener to one network, `::` listens on IPv6. A value that is not an IP address stops the start; the banner and "Effective configuration" show the addresses in use. Both listeners may now share a port when their addresses don't overlap (e.g. `127.0.0.1` and `127.0.0.2`); `0.0.0.0` and `::` overlap every address, and an IPv4-mapped address (`::ffff:127.0.0.1`) is the IPv4 one. The banner offers `http://localhost:PORT` only when the web UI listens on every interface, otherwise the bound address itself. HTTP Basic auth, the issue's optional second step, is not part of this change.
- **Cross-site requests are refused** — the web server did not check where a browser request came from, so any page open in a user's browser could read the live feed over the WebSocket (`Origin` was never checked), empty the store with a cross-site `POST /api/clear`, and — via DNS rebinding — read the REST API. A new middleware (`guard_cross_site`, `src/web.rs`) now refuses with `403`: requests whose `Host` is not an IP literal, `localhost` or a name in the new `server.allowed_hosts`; and, on `/ws` and every state-changing method, an `Origin` that is not this server. Requests without `Origin` (curl, scripts) are unaffected. `server.allowed_hosts` entries with a port, scheme or path are warned about at startup, and a trailing dot (`harux.klinik.local.`) matches. The CSP gains `frame-ancestors 'none'`, and `X-Content-Type-Options: nosniff` is sent. (#227)

### Fixed
- **ORU^R01 without OBX is no longer flagged** — `validate_oru_r01` raised `MISSING_SEGMENT` (red badge) when a result had no OBX, although the OBSERVATION group is optional in v2.5.1 (an order-level result with OBR only) (#250). OBX is no longer required; OBR-2/OBR-3 are treated as conditional (one order number is enough) and OBX-2 is required only when OBX-5 is valued. New fixture `oru_r01_without_obx.hl7`.
- **Impossible dates and times are reported** — DT/TS validation only checked month 01–12 and day 01–31, so 30 February, 25:61:99 and odd lengths passed (#238). Dates are now checked against the calendar (`chrono`), TS must have 4/6/8/10/12/14 digits with hours 00–23 and minutes/seconds 00–59, a fraction of 1–4 digits only after the seconds and a `+/-HHMM` offset (only after at least a full date); NM needs at least one digit. A TS warning names the TS type (`expected a timestamp (TS) …: 2023-02-29 does not exist`). No valid fixture gets a new warning.
- **WebSocket events arrive in the order the store changed** — `insert`, `add_tag`, `remove_tag` and `toggle_bookmark` broadcast their event after releasing the store lock, while eviction and clear broadcast under it (#232). Between the unlock and the send another task could change the store and send its own event, so two users tagging the same message at once could leave a browser showing a tag list without one of the tags (about 1 in 100 races), and a message larger than the whole store could be reported as evicted before it was reported as new (a row for a message that no longer exists). All events are now sent while the write lock is held. `test_insert_event_precedes_its_eviction` (`src/store.rs`, multi-thread runtime, 2,000 rounds) failed on the old code on both machines it was tried on, but probabilistically (round 6 and round 890); `test_concurrent_tagging_events_match_store` is a smoke test whose window is too small to reproduce reliably on every machine. The ordering rests on the rule, which a `grep tx.send` re-checks: all four send sites (`insert`, `mutate_meta`, `evict_now`, `clear`) are under the lock.
- **Bookmarks survive a reload** — the UI loaded only the newest 1,000 messages, so after a reload a bookmark older than that was in neither the list, the Bookmarks filter nor the badge, although the store kept it protected (#231). `GET /api/messages` gains `include_bookmarks=true` (also `1` / `yes`), which adds every older bookmarked message in store order (bounded by the bookmark budget), and the UI loads with it.
- **Messages arriving during a list (re)load are no longer lost** — `loadMessages()` replaced the client state with the server's list when the response arrived, so a message (or tag, bookmark, eviction) that came over the WebSocket while the request was in flight vanished until the next reload (#239). WebSocket events now go through `handleServerEvent()`; during a load they are queued and replayed in order after the snapshot (messages already in it are skipped), and a newer load supersedes an older one; after a replay the header total is resynced from `/api/stats` at once. `tests/js/load.test.mjs` covers the race, duplicates, updates and clears during a load, and superseded loads.
- **The export gives back exactly the bytes that arrived** — `GET /api/export` wrote each message's decoded text: a Latin-1 message (`ü` = `0xFC`) came out as UTF-8 (`0xC3 0xBC`) while its MSH-18 still said `8859/1`, and the final segment terminator was trimmed (#230). Now `raw` keeps the text as received (no trim), and each message records how to restore its bytes (`WireForm` in `src/hl7/types.rs`): UTF-8 payloads are `raw` itself, other charsets are re-encoded with the encoding they were decoded with, and only a payload no encoding reproduces (the decode replaced invalid bytes) keeps a copy of its original bytes — so a Latin-1 MDM attachment is still held once. `tests/mllp_tcp.rs` sends UTF-8, declared and undeclared Latin-1/Windows-1252 and invalid Big5 over MLLP and requires the export to match the received frames byte for byte.
- **A broken configuration stops the start** — `Config::load` never refused to start (#233): one value of the wrong type discarded the whole `harux.toml` (Harux came up on ports 2575/8080 and default limits, with one warning on stderr), typos in keys and invalid `MLLP_PORT` / `WEB_PORT` were ignored, and `max_messages = 0` was accepted. Now every section rejects unknown keys, a read/parse error or invalid port variable is an error naming file, key and reason, and values that can't work (zero limits or timeouts, MLLP and web on the same port, `store.max_memory_mb` below `mllp.max_message_size_mb`) are reported together. `logging.level` / `RUST_LOG` must name real levels — a typo like `warm` used to be taken as a target name and silently switched all logging off. Harux exits with that message instead of starting. The log now says which file was loaded. Covered by unit tests and by `tests/config_startup.rs`, which runs the real binary.
- **Diff compares every occurrence of a segment** — the diff paired segments by name and compared only the first of each, so two ORU^R01 that differed only in their second OBX (potassium 4.1 vs. 7.9) were reported as "✓ Messages are identical". Segments are now paired by name *and* occurrence (`pairSegments` in `static/diff.js`): OBX[1] with OBX[1], OBX[2] with OBX[2]; repeating segments are labelled `OBX[2]`. An occurrence present on one side only counts as a difference ("1 segment only in one message"), so messages with a different number of OBX are never "identical". The pairing is covered by `tests/js/diff.test.mjs`, the first automated test of frontend logic (`node:test` + `node:vm`, no dependencies), which CI now runs. (#228)
- **Validation no longer flags standard-conformant messages** — some rules were stricter than the HL7 v2.5.1 message definitions, and two of them raised `MISSING_SEGMENT` (the red badge) on correct messages (#229):
  - `ORM^O01` required PID and OBR. The patient group is optional and the order detail is a choice (OBR, RXO, RQD, …), so a pharmacy order with `ORC` + `RXO` was flagged red. Only `ORC` (with ORC-1) is required now; `OML^O21` likewise.
  - `ADT^A20` (bed status: MSH, EVN, NPU) required PID; it now requires NPU instead. `ADT^A19` (query) is no longer checked for PID.
  - PID-8 (administrative sex) was reported as required for ADT; it is optional.
  - A PID that A19/A20 do carry is still checked (PID-3, PID-5).
  - The three messages are fixtures in `tests/messages/valid/`, and the fixture test now fails if any valid fixture gets a `MISSING_SEGMENT`.
- **`store.max_memory_mb` now bounds real memory** — the store accounted string lengths only and ignored the structures around them: 56 bytes per `Hl7Field` (also for empty fields), the segment and field vectors, allocator overhead, and its own per-entry bookkeeping. Real memory was about 10× the accounted bytes for ordinary ADT traffic and up to 75× for frames made mostly of separators — two 10 MB `|||…` frames took the process from 42 MB to 1.2 GB with 20 MB accounted and no eviction. (#226)
  - `Hl7Message::estimated_bytes` now counts every buffer by capacity plus allocator overhead (`heap_bytes` in `src/hl7/types.rs`), and the store adds its per-entry cost (`entry_overhead` in `src/store.rs`). Checked with a counting allocator: within 0–10 % of the real heap, never below it.
  - Less real memory per message: field and segment vectors are shrunk after parsing, and `typical_segments` / `typical_segment_descriptions` borrow from the static registry instead of being copied into every message. A 731-byte ADT now holds about 13 KB instead of 18 KB.
  - Frames with more than 250,000 fields are stored unparsed with a parse error (`MAX_FIELDS_PER_MESSAGE`), which bounds the parse-time spike before accounting can see it.
  - `/api/stats` gains `store_bytes` and `store_max_bytes`.
  - `tests/alloc_accounting.rs` keeps it honest: with its own counting allocator it requires the estimate to match the modeled heap of real messages (never below, at most 5 % above), so a heap-owning field that is not counted fails the build. The model is glibc's; on Windows it over-counts short strings, so the store evicts slightly early there.
  - Measured with a 64 MB limit: 2,000 ADT messages are accounted at 27.7 MB and grow the process by 28.6 MB; 32,000 ADT messages leave the store at 59 MB and the process at 72 MB.
- **Parser/validator panics on multi-byte characters** — `parse_message` quoted the start of a non-MSH payload with a byte slice (`src/hl7/parser.rs`), and `validate_ts` sliced a timestamp at byte 8 (`src/validation.rs`). A character such as `ä` across that offset panicked the connection task: no ACK, nothing stored, not counted. Both now work on character boundaries; a garbled TS is an `INVALID_DATATYPE` warning. (#222)
- **A panic while processing a frame no longer drops it** — decoding and parsing run under `catch_unwind` (`ingest` in `src/mllp.rs`): a parser bug becomes a stored parse error plus NACK `AE`, and the connection stays open. `active_connections` is un-counted by a drop guard on every exit path, so it can no longer leak (it showed `113 / 100` after 113 panics and held shutdown until the timeout). (#235)
- **Over-limit frames are answered and visible** — a frame above `mllp.max_message_size_mb` used to close the connection without reply, entry or counter. It is now answered with a reject (`AR`, in the sender's delimiters and with MSA-2 from MSH-10 when its header is readable, reason in MSA-3), stored as a parse-error entry holding only its first 4 KB, counted under `received` / `parse_errors`, and the rest of the frame is skipped — the connection stays usable. Complete frames above the limit are rejected the same way. (#223)
- **A failed `accept()` no longer stops Harux** — errors such as `EMFILE` used to end the MLLP task and with it the whole process (exit code 0). They are now logged (first of a streak, and the recovery), resource errors back off 100 ms, and the listener keeps running. If a server task does end unexpectedly, Harux exits with a non-zero code. (#224)
- **Graceful shutdown waits for frames in flight** — the drain waited for one `Notify` wake-up, and the permit stored by any earlier connection close made it return at once ("All MLLP connections drained" while a frame was still arriving). `mllp::wait_for_drain` now waits until the connection count is zero. (#241)
- **SIGTERM triggers the graceful shutdown** (Unix) — `systemctl stop`, `docker stop` and `kill` used to end the process immediately. (#225)
- **An unwritable log file no longer stops Harux** — since the switch to `tracing_appender::rolling::daily` (#162), a log directory that could not be created panicked at startup (exit code 101), a regression of #113 (#234). The appender is now built with the fallible builder (`LogTarget::appender`, `src/logging.rs`); on failure Harux logs to stdout only, says why on stderr and in the log, and "Effective configuration" shows the file as unusable. A `logging.file` that names no file (`logs/`, `logs/.`, `.`) stops the start instead of logging to `./logs.YYYY-MM-DD` next to the directory. The 0.4 entry for #113 is accurate again.
- **Daily log files are pruned** — with `logging.file` set, one file per day was written and none was ever deleted (#240). `logging.max_files` (default 14, `0` = keep all) keeps the newest daily files, checked at startup and hourly. Harux prunes them itself instead of using `tracing-appender`'s `max_log_files`, which deletes *every* file starting with the log name (with `file = "harux"`, also `harux.exe` and `harux.toml`); only files named exactly `<file>.YYYY-MM-DD` are touched.
- **A damaged MSH header is a parse error, not a message** — a letter or digit right after `MSH` (`MSHARM|…`, `MSHU^~\&|…`) was taken as the field separator, so the frame was split at every `A` or `U`, ACK'd, and the ACK — written in those delimiters — could not carry `UNKNOWN` or the control ID intact (#243). `parse_delimiters` now rejects letters and digits as delimiters; such a frame gets a NACK and shows as a parse error. Found by the new fuzz test. This is a deliberate tightening: HL7 only recommends `|^~\&` and leaves delimiters to the interface agreement, so a sender that negotiated a letter or digit as a separator would now get a NACK where it got an ACK before.
- **The last segment keeps its trailing characters** — the parser trimmed the whole message, so trailing spaces were cut off the last segment's last field, and only off that one; every other segment kept them (#243). Only leading whitespace before `MSH` is skipped now; `raw` was and is unchanged.
- **Documentation matches the code again** — the user-facing docs had drifted (#242): the README advertised a JSON export (it has been an MLLP-framed `.hl7` file since #160, byte-faithful since #230) and a "drop-in replacement for HL7 Inspector" although sending, editing and replay are still planned; the export button was titled "Export JSON"; `./test.sh` does not exist (it is `tests/test.sh`); `docs/PROJECT_OVERVIEW.md` described a single `app.js`, an 80-type registry in Rust code, "evict the oldest 10 %", a closed connection for oversized frames, axum 0.7 and broken links. README, `SECURITY.md`, `CONTRIBUTING.md`, `docs/PROJECT_OVERVIEW.md` (now with a configuration table and the full WebSocket event list), `docs/ROADMAP.md`, `docs/STYLE_GUIDE.md`, the PR template and `examples/harux-example.toml` (now every key) were corrected against the code.
- **A NACK says why the frame was rejected** — a frame that failed to parse was answered with the generic `Message parse error`, so the sender's log never showed the reason and someone had to open Harux to find it (#218). A NACK now carries `Message parse error: <reason>` in MSA-3, cut to 80 characters (the field's v2.5 length), **and** an ERR segment: ERR-3 the HL7 error code from table 0357 (`100` Segment sequence error for parse errors, `207` Application internal error for a parser panic — recognised by the `PARSER_PANIC_PREFIX` constant `ingest` writes, covered by `test_reply_error_codes`), ERR-4 `E`, ERR-8 the reason cut to 250 characters. The `AR` reject for oversized frames gets ERR `207` as well. MSA-3 is deprecated since v2.4 in favour of ERR but still what many receivers read, so both are sent. All text is escaped and cut by characters before escaping (marker `...`), so neither a multi-byte character nor an escape sequence is split.
- **ACKs and NACKs are written in the sender's charset** — replies always went out as UTF-8 bytes without MSH-18, so a Latin-1 sender (`8859/1`, typical for Orchestra on Windows) got its echoed MSH-3/4 back as mojibake, and — with #218 — the quoted start of a broken frame too (#266 review). The reply is now encoded with the charset the payload was decoded with (`reply_bytes`, from `WireForm`) and declares the sender's MSH-18 unless that declaration had to be overridden (`CHARSET_FALLBACK`, `reply_charset`). Text Harux writes itself is ASCII (the cut marker is `...`, parse errors use `-` instead of `—`), so it fits any charset. `reply_is_written_in_the_senders_charset` (`tests/mllp_tcp.rs`) checks the bytes over TCP and fails when replies are written as UTF-8.
- **The client buffer no longer drops extra messages when bookmarks are loaded** — `trimClientBuffer()` computed the excess from the whole buffer, bookmarked and selected messages included, while its early exit counted only the droppable ones. With many bookmarks, one flush dropped as many extra rows as there were bookmarks and the next dropped none. The cap now counts droppable messages only: `CLIENT_MESSAGE_CAP` plus the exempt ones, as documented (#204, found by the new JS tests).
- **The bookmark counter changes at most once per event** — `updateMessageBookmark` adjusted `totalBookmarkCount` separately for the list and the pending buffer, so a message held in both would have been counted twice (#184). Since #239 a message is never in both, but the counter no longer depends on that.
- **Frontend errors that were swallowed are logged** — saving/restoring the session view and restoring a pinned diff message failed silently; they now log with `console.debug`, including a pinned message that is no longer stored (HTTP 404) (#190). On the server side, a failed ACK/NACK write is already logged (`send_reply` in `src/mllp.rs`).
- **Opening a large MDM no longer freezes the UI** — a multi-MB Base64 attachment was laid out in full in the field table (twice: value and components), the Raw tab and the JSON tab, which blocked the tab for seconds, nearly all of it in Layout/Paint (#215). Values, component leaves, raw lines and JSON strings above 2,000 characters now show their first 1,000 characters and a size note ("… 5.0 MB in total, shortened for display"). Copying a field still gives the complete value (`fullFieldValues`, not the cell text), "Copy All" the complete message, and the diff compares full values. Measured in headless Chromium with a 5 MB attachment: Segments 13–23 s → 0.16–0.19 s, Raw ~1.8 s → 0.15–0.18 s, JSON 4.5–7 s → 0.15–0.16 s (wall time including the fetch).
- **Resuming after a long pause is fast** — `buildMessageRow` parsed a template string with two inline SVGs and attached two closures for every row, about 0.8 ms per row (#202). Rows are now cloned from a skeleton parsed once, icons are cloned from a cache, and clicks/Enter go through the existing `data-action` delegation (`select-message`). Resuming with 2,000 buffered messages: 1.38 s → 0.13 s until painted (flush 451 → 97 ms).
- **The idle UI no longer keeps the main thread busy** — the listening dot's `box-shadow` pulse repainted at 60 fps, and the per-second relative-time update rewrote and re-laid out every fresh row (#216). The pulse is now a pseudo-element animating `transform`/`opacity` (compositor-only, same look), unchanged labels are not rewritten, and rows use `content-visibility: auto` with an exact intrinsic size (61 px), so off-screen rows skip layout and paint; the scrollbar is unchanged (identical `scrollHeight`). With 2,000 rows: idle main thread 37.6 % → 4.2 %, and 1.1 % once the rows' labels have settled.

### Changed
- **ACK after store** — a message is now stored before its ACK/NACK is written, so an ACK means the message is in the store.
- **`mllp::serve`** accepts an already bound `TcpListener`; `start_mllp_server` binds and calls it.
- **One agent guide** — `CLAUDE.md`, `AGENTS.md` and `.jules/` repeated the same rules in different words and had fallen behind the code (planned work that shipped in 0.4, a completed milestone named as next, differing dependency rules, an XSS "fix" that reintroduces inline handlers) (#246). `AGENTS.md` is now the single source of truth with the full architecture notes; `CLAUDE.md` and `GEMINI.md` import it (`@AGENTS.md`) and add only tool-specific lines; planning facts live only in `docs/ROADMAP.md`; the `.jules` notes and the handoff/audit documents are marked historical and the superseded `escJS` advice is corrected.
- **`message_structure` is documented as informational** — MSH-9.3 is shown in the detail JSON; validation deliberately dispatches on message type and trigger event, since MSH-9.3 is optional and often missing in real traffic (#186).
- **Each WebSocket event is serialized once, not once per viewer** — every connected browser's task turned the same summary into JSON itself, via a `serde_json::Value` tree, so N viewers meant N identical serializations per message (#196). The broadcast channel now carries `Arc<EventFrame>`: the event plus its frame, rendered by the first subscriber (`EventFrame::cached_json`, `OnceLock`) and reused by the others; `ws_event_json` (`src/web.rs`) serializes straight into a string. The wire format is unchanged (`ws_event_json_keeps_the_wire_format`). With 20 connected clients and 5,000 messages the server used 1.8 s of CPU instead of 2.25–2.42 s.

### Added
- **Older messages can be loaded and searched in the UI** — the UI loads the newest 1,000 messages (plus bookmarks); everything older the store held was out of reach, and filters only covered what was loaded (#198). The note at the end of the list now offers **"Load 500 older"** — `GET /api/messages?before=<id>` pages by cursor, since offsets shift as messages arrive — and, while a search is active, **"Search older on the server"** (#197): `GET /api/search?before=<id>` searches the part not loaded and continues below its last hit. Found messages are merged in arrival order and raise the client cap (`olderLoaded`) so new live messages don't trim them at once; a reload resets it. `/api/search` was unused by the UI and matched differently from the client filter; it now uses `SearchQuery` (`src/store.rs`), which mirrors `getParsedQuery`/`matchesSearch`: `has:warnings`/`has:errors`, tags, Unicode case folding. `before` cannot be combined with `offset` or `include_bookmarks` (`400` instead of silently ignoring one).

## [0.8.0] – 2026-11-10 – HL7 Conformance

> Phase 3 of the May 2026 code audit. Harux now reads and answers HL7 the way the standard describes:
> - Repetitions, sub-components and escape sequences are parsed, and the detail view shows them decoded.
> - Patient ID, patient name and validation no longer trip over repeated fields.
> - A wrong or missing MSH-18 charset falls back with a visible warning instead of garbling text.
> - ACK and NACK come from one builder, written in the sender's own delimiters.
>
> MDM attachments in ED fields also take one copy less RAM.

### Upgrade Notes
- **API change in `GET /api/messages/{id}`:** `fields[].components` is replaced by `fields[].repetitions`. It is a `[repetition][component][sub-component]` array of escape-decoded strings and is present only for fields that contain a separator or an escape. `value` still holds the field exactly as received, and the message gains `delimiters` (e.g. `"|^~\\&"`). The bundled web UI is updated, so only custom REST clients are affected. List summaries, WebSocket events and the export are unchanged. (#185)
- **ACK/NACK wire changes**, all HL7-conformant (#187):
  - ACKs are written in the **sender's** delimiters and echo its MSH-11 processing ID. Before, they always used `|^~\&` and `P`.
  - NACKs now carry their own MSH-10 control ID.
  - Receivers that hard-coded `|^~\&` or `P` for ACKs from senders with non-default delimiters or `T`/`D` processing should be checked.
- **Charset decoding changes** (#188):
  - Payloads that are not valid UTF-8 and declare no MSH-18 are now decoded as Windows-1252 (Latin-1) instead of having `U+FFFD` replacement characters.
  - Payloads that declare a charset that doesn't fit the bytes fall back the same way.
  - Both cases carry a new `CHARSET_FALLBACK` validation warning on MSH-18. It counts towards the validation badge and filter.
- **Patient ID and patient name now come from the first repetition** and are escape-decoded. For example, `ID1~ID2` gives `ID1` and `O\T\Brien` gives `O&Brien`. An empty CX.1 now gives no patient ID instead of an empty one. Message lists and searches show the corrected values for newly received messages. (#185)
- **No configuration change required.**
- **Internal Rust API** (only relevant if you use `harux` as a library):
  - `Hl7Field::components` and `Hl7Field::component(i)` are replaced by `repetitions(d)`, `leaf(d, rep, comp, sub)` and `structure(d)`.
  - `Hl7Message` gains `delimiters` and is serialize-only (no `Deserialize`).
  - `Hl7Segment` gains `delimiters` and a hand-written `Serialize`.
  - New modules `hl7::escape` and `hl7::charset`.

### Added
- **Repetitions, sub-components and escape sequences are parsed** (#185). Previously the parser only split on `^`, which caused several problems:
  - A repeated PID-3 (`ID1~ID2`) became the patient ID `ID1~ID2`.
  - Sub-components (`&`) and escapes (`\T\`, `\.br\`) showed up raw in the detail view.
  - A repeated date such as `20240101~20240202` raised a false `INVALID_DATATYPE` warning.
  - The detail view always drew `^` between components, whatever the sender's delimiter was.

  Now:
  - Patient ID and name come from the first repetition, escape-decoded (`O\T\Brien` → `O&Brien`).
  - Datatype validation checks each repetition separately and names the failing one (`PID-7[2]`).
  - The detail view shows `value` raw next to its decoded structure, drawn with the sender's own separators. Repetition separators are highlighted, `\.br\` becomes a real line break, and tooltips give HL7 positions such as `PID-3[2].4.1`.

  The decoding table is in `src/hl7/escape.rs`. Sequences that can't be decoded without more context (`\Xhh\`, `\Z…\`) stay verbatim.

### Fixed
- **Charset handling: one MSH parser, and a fallback instead of mojibake.** `mllp.rs` used to read MSH-18 with its own byte scanner, separate from the parser, and the two disagreed:
  - The scanner applied a charset even when the parser rejects the MSH-2 encoding characters.
  - It only stopped at `\r`, so with `\n` segment endings MSH-18 read as `8859/1\nPID…` and the charset was ignored.
  - It used the whole repeating MSH-18 value (`8859/1~UNICODE UTF-8`) as the charset name.

  Decoding now lives in `src/hl7/charset.rs` (`decode_payload`), built on the parser's own byte-based `parse_delimiters` and a shared `msh_split_index`. A wrong or missing declaration no longer turns silently into garbled text:
  - `8859/1` declared but UTF-8 sent: previously `MÃ¼ller`, now decoded as UTF-8.
  - UTF-8 or nothing declared but Latin-1 bytes sent: previously `M�ller`, now decoded as Windows-1252.
  - Unsupported MSH-18 values (e.g. `UNICODE UTF-16`): previously decoded silently as lossy UTF-8; they now fall back the same way, with a warning.

  Each fallback is logged and shows up on the message as a `CHARSET_FALLBACK` validation warning on MSH-18. HL7 table 0211 names such as `UNICODE UTF-8`, `ISO IR100`, `BIG-5` and `GB 18030-2000` are now recognised. ASCII-only payloads, such as Base64 MDM attachments, skip all of this, so a 9 MB message round-trips in about 47 ms as before. (#188)

### Changed
- **Less RAM for MDM attachments** (#185). The field structure is no longer stored: it is derived from `Hl7Field::value` on demand and computed only when a message's detail JSON is serialized. As a result, an ED attachment (`^application^pdf^Base64^…`) is no longer held a third time as a parsed component. With 10 × 9.4 MB ED messages, the server's resident memory drops from 330 MB to 247 MB.
- **ACK/NACK built by one shared builder** — `build_ack` and `build_nack` (`src/hl7/parser.rs`) had drifted apart. Both are now thin wrappers around one `render_ack`, so the MSH/MSA layout exists once. Visible on the wire:
  - The NACK for an unparseable frame now carries its own MSH-10 control ID (was empty).
  - The ACK echoes the original MSH-11 processing ID (`T`/`D` test senders were answered with `P`).
  - It falls back to `2.5` when the original has no MSH-12, and to MSA-2 `UNKNOWN` (as the NACK does) when it has no MSH-10.
  - It sends plain `ACK` instead of a dangling `ACK^` when MSH-9 has no trigger event.
  - ACKs are written in the **sender's delimiters**, so values echoed from a sender with non-default delimiters (e.g. `#*~\&`) stay valid instead of corrupting the ACK's field structure.
  - MSA-3 text is HL7-escaped (`\F\ \S\ \T\ \R\ \E\`).
  
  The public signatures are unchanged. Verified by round-trip tests that parse every generated ACK/NACK back, and against a live server over MLLP. (#187)
- **Tests — no sleep-based synchronisation left in the Rust tests** — the last test that exercised the real background eviction task (`test_byte_based_eviction_triggers` in `src/store.rs`) slept 50 ms and hoped the task had finished. It now runs on the multi-threaded runtime, so the background task really runs concurrently with the test, and waits with the helper `wait_until_within_limits`: it subscribes to the store's existing broadcast channel *before* checking the state and re-checks on every event (`Evicted` is sent under the write lock after each pass that evicts), so a pass finishing in between can't be missed; a 5 s timeout turns a broken eviction loop into a clear failure instead of a hung CI. No production code was added for this. The other eviction tests already drive `evict_now()` directly (#178). The pointless 50 ms sleep at the end of `tests/benchmark_concurrent_insert.rs` (which only asserts insert latencies) is removed. Verified on the multi-threaded runtime under full CPU load; with eviction disabled the test fails after 5 s with "background eviction did not bring the store within limits". (#191)

## [0.7.0] – 2026-11-06 – Memory Footprint & Hot-Path Performance

> Phase 2 of the May 2026 code audit: large messages take about half the RAM and parse 2–3× faster, tagging/bookmarking no longer copies whole messages under the store lock, and Export streams instead of duplicating the store. Same configuration, roughly twice the effective capacity for MDM traffic.

### Upgrade Notes
- **API change in `GET /api/messages/{id}`:** `segments[].raw` is removed, and `fields[].components` is omitted for single-component fields (read the field `value` instead). The bundled web UI is updated; only custom clients of the REST API are affected. List summaries (`GET /api/messages`), WebSocket events and the export format are unchanged.
- **More messages fit in the same memory cap.** The store accounts for real heap usage, and each large message now uses about half as much, so `store.max_memory_mb` holds roughly twice as many MDM messages. Lower the cap if you relied on the old effective count to bound RAM.
- **No configuration change required.**
- **Internal Rust API** (only relevant if you use `harux` as a library): `Hl7Message` no longer has `tags` / `bookmarked` (see `MessageMeta`), `MessageStore::get_by_id` returns `MessageSnapshot`, `list_all_raw` is replaced by `payload_snapshot`, `Hl7Segment::raw` is removed and descriptions are `Cow<'static, str>`.

### Fixed
- **Export no longer duplicates the whole store in memory or stalls ingest** — `GET /api/export` used to clone every stored `raw` String into a `Vec<String>` while holding the store's read lock (`list_all_raw`), then copy all of it again into one response `Vec<u8>`: about twice the stored payload as a transient spike, and a long read lock that delayed the next `store.insert` — and with it the ACK on the MLLP path. The export is now streamed: `MessageStore::payload_snapshot` holds the lock only to clone the payload `Arc`s (pointer copies), and `MllpExportStream` (`src/web.rs`) produces `VT raw FS CR` frames as the client reads — payloads ≥ 64 KiB go out zero-copy via `Bytes::from_owner`, smaller ones are coalesced into ~64 KiB chunks — with an exact `Content-Length`. Measured with 120 × 1 MB MDM messages: the export added **237 MB** to the server's peak memory before and **0 MB** after, finished in 0.17 s instead of 0.32 s, and produced a byte-identical file. The MLLP framing constants now have a single definition in `src/mllp.rs`, which the export reuses. Added `futures-core` as a direct dependency for the `Stream` trait — it was already in the dependency tree via axum/tokio. (#195, refs #199)

### Changed
- **Parser holds each message's payload twice instead of four times — about half the RAM per MDM, 2–3× faster parsing** — every parsed message kept its text as `Hl7Message::raw`, again per segment as `Hl7Segment::raw`, again per field as `value`, and once more as `components[0]` even for single-component fields; every field and segment also cloned its dictionary description. For a multi-MB Base64 OBX-5 that is four copies of the attachment. Now: `Hl7Segment::raw` is removed (the UI's "copy segment" derives the line from the message `raw`, split exactly like the parser); `Hl7Field::components` is only filled when a field has two or more components (`Hl7Field::component(i)` reads both cases; validation uses it); field and segment descriptions are `Cow<'static, str>` borrowed from the static dictionary. Measured: 120 × 1 MB MDM messages need **254 MB RSS instead of 494 MB**, a message's detail JSON shrinks from 4.2 MB to 2.1 MB, and `parse_message` (release build) takes 4.2 ms instead of 10.9 ms for 5 MB, 8.5 ms instead of 26.4 ms for 10 MB, 5 µs instead of 10 µs for a small ADT. Since the store's byte accounting counts real heap usage, `store.max_memory_mb` now holds roughly twice as many large messages. **API note:** in `GET /api/messages/{id}`, `segments[].raw` is gone and `fields[].components` is omitted for single-component fields (the bundled UI is updated; external consumers should read the field `value`). Moving validation off the MLLP hot path (also proposed in #180) was measured and not done: at ≤ 8.5 ms for the 10 MB maximum and 5 µs for typical messages it does not justify mutating the now-immutable payload (#192) after insert. (#180)
- **Store — tagging/bookmarking no longer deep-clones messages under the write lock** — tags and the bookmark flag lived inside the `Arc`-shared `Hl7Message`, so `mutate_message` used `Arc::make_mut`; whenever a reader held a snapshot (e.g. a `GET /api/messages/{id}` being serialized) that copied the entire message — raw payload, segments, fields, several MB for an MDM — while holding the store's write lock, stalling every reader and the MLLP ingest path. Tags and bookmark now live in a separate `MessageMeta` (`src/hl7/types.rs`), stored next to the immutable payload in a `StoredEntry` (`src/store.rs`); `mutate_meta` only touches that small struct, so no copy-on-write can happen. Each entry also caches its accounted bytes (computed once at insert, adjusted by the metadata delta), so eviction no longer re-walks parsed messages under the lock. `get_by_id` returns a `MessageSnapshot` (payload `Arc` + metadata) that serializes with `#[serde(flatten)]` to the exact same JSON as before; `Hl7MessageSummary::new(msg, meta)` replaces `From<&Hl7Message>`. **Wire format unchanged; internal Rust API changed** — `Hl7Message` no longer has `tags` / `bookmarked`, `MessageStore::get_by_id` returns `MessageSnapshot` instead of `Arc<Hl7Message>`, and the `From<&Hl7Message> for Hl7MessageSummary` impl is gone (relevant only to code using the `harux` library crate). `AGENTS.md` brought in line with the current store design (it still described the pre-#178 10 %-eviction and removed constants) and with the prepend hot path. New tests prove a held snapshot shares the payload allocation across tag/bookmark mutations (on the old code the same scenario produced a fresh allocation) and that the detail JSON stays flat. (#192)

### Fixed
- **Detail panel no longer shows the wrong message after quick clicks** — `selectMessage` (`static/render.js`) set `state.selectedId` immediately but applied whatever `fetch` response arrived last, so clicking A then B could leave row B highlighted while the panel showed A when A's (larger) response came back later. The same race existed in `toggleDiffPin` (`static/diff.js`) and in the session pin restore in `loadMessages`, where a stale response could re-pin a message the user had already replaced or unpinned. Each call now takes a sequence number (`state.selectRequestSeq` / `state.diffPinRequestSeq`) and applies its response only if no newer call started meanwhile — checked after both the `fetch` and the body read; `selectMessage` additionally requires the selection to be unchanged (e.g. not cleared by a server eviction). In the same class: a diff pin whose message the server evicts is now dropped (it previously survived with no row to unpin it), and a `selectMessage` whose response is an HTTP error (message evicted between render and click) now clears the highlight and the panel with a toast instead of leaving the previous message next to the new row. Verified with Playwright by delaying one message's response: before the fix the panel showed the wrong message and the stale pin won, after it the last click wins in all three paths. (#183)
- **"No messages received yet" no longer shown for an empty filter result** — the list's empty state always showed the onboarding card (listening port + CLI snippet), even when messages had arrived and only the search / bookmark / validation filter hid them all. `#empty-state` now has a second card, "No matching messages", and the new `showEmptyState()` (`static/render.js`) picks it whenever a client-side filter is active and messages are loaded; the onboarding card remains for a genuinely empty store (e.g. after Clear). The new card has a "Clear filters" button (`clearFilters()` in `static/app.js`) that resets search, bookmark and validation filters in one go. (#203)
- **Browser tab no longer grows without bound** — the server is capped at `store.max_messages` / `store.max_memory_mb`, but the client never trimmed anything: `addMessage` / `flushAndRender` in `static/ws.js` kept every received message in `state.messages`, and `prependMessagesToList` kept every `.message-row` in the DOM, so a tab left on a busy Orchestra feed for hours accumulated hundreds of thousands of objects and rows until it froze. `state.messages` now holds at most `CLIENT_MESSAGE_CAP` (2000, `static/util.js`) messages plus the exempt bookmarked and selected ones — bookmarks are bounded server-side by the bookmark budget, so the buffer is bounded overall (≈ 5000 rows worst case with defaults). After each flush `trimClientBuffer()` drops the oldest non-exempt messages (with an O(1) early exit when only exempt entries exceed the cap) and undoes their share of the incremental counters via the shared `forgetMessageCounters()`. The matching rows are removed bottom-up by the new `removeRowsFromList()` in `static/render.js` — a plain sibling walk with a Set lookup, together with any group header left empty — instead of rebuilding the list; the server-eviction handler uses the same helper. While paused, `pendingMessages` is capped the same way. Because filters and search run client-side, a note at the bottom of the list — or above the empty state when nothing loaded matches — (`updateTruncationNote()`) now says when the server holds more messages than the view has loaded, so a search for a trimmed message no longer silently looks like "never arrived" (server-side search/history: #197, #198). The header `total` pill shows the server total (`state.totalMessagesCount`, refreshed on every 3 s stats poll, also while paused) instead of the client buffer length; `loadMessages` keeps it at least as large as what it loaded. Verified with Playwright against a live server (5100 messages incl. pause/resume and bookmark-filter phases): buffer and DOM stay at 2000 rows in lock-step, no orphaned headers, all counters match a full recount, bookmarked and selected rows survive, the note is shown and stays last, no console errors. (#177)
- **Evicted messages disappear from the UI; lost bookmarks are announced** — eviction previously only logged, and the frontend refreshed rows only on `new_message` / `cleared`, so evicted rows lingered and returned 404 on click. With the #178 bookmark budget this would have meant losing bookmarks silently. Each eviction pass now broadcasts `StoreEvent::Evicted(ids)` (sent under the write lock, like `clear`), `src/web.rs` forwards it as the WS event `evicted`, and `removeEvictedMessages` in `static/ws.js` drops those IDs from `state.messages` / `pendingMessages`, undoes their share of the incremental counters (validation, bookmark, source counts), clears the detail panel if the selected message was evicted, rebuilds the list once, and shows a toast when bookmarked messages were evicted. A single message larger than the whole byte limit is now dropped with a dedicated `warn!` naming its ID and size instead of only the generic eviction line. (#178 review)
- **Store byte accounting no longer drifts downward** — `MessageStore::insert` added a message's `estimated_bytes()` once at insert time, but later mutations through `mutate_message` (`add_tag`, `remove_tag`) changed the message's size without updating `current_bytes`. Eviction then subtracted the *post-mutation* `estimated_bytes()`, so every tagged-and-evicted message pulled `current_bytes` below the real total; over the server's lifetime the byte trigger fired later and later and real memory silently exceeded `store.max_memory_mb`. `mutate_message` in `src/store.rs` now measures `estimated_bytes()` before and after the mutation and applies the signed delta to `current_bytes` — growing tags add, removed tags subtract, bookmark toggles and no-op mutations leave it unchanged. New tests assert the invariant `current_bytes == Σ estimated_bytes()` after tag/untag/bookmark, after an eviction pass over tagged messages, and that `clear()` returns it to 0; both fail without the fix. (#179)
- **Store memory cap can no longer be bypassed (server OOM)** — `run_eviction_loop` in `src/store.rs` had three overlapping gaps that let the store grow past `store.max_memory_mb`: (1) when the oldest messages were all bookmarked, eviction skipped them, freed nothing and only logged — bookmarking a handful of multi-MB MDM messages lifted the cap entirely; (2) eviction removed `len / 10` messages, so with fewer than 10 (large) messages `target_count == 0` and nothing was evicted at all; (3) eviction targeted a fixed 10 % of the *count* rather than the byte limit, so one pass could leave the store well above its limit. Eviction is now a single deterministic pass `StoreInner::evict`: first, bookmarks exceeding the new **bookmark budget** (`store.bookmark_budget_percent`, default 50 %, clamped to 80 %) are evicted oldest-first; then the oldest non-bookmarked messages are evicted until **both** bytes and count are at or below 90 % of their limits (low watermark). Because the budget is capped below the watermark, every pass brings the store back under its limits. The now-unreachable "all candidates bookmarked" warning is removed; a `warn!` is logged instead whenever bookmarks are evicted. Eviction tests now drive the pass directly on a store without the background task, so they no longer depend on `sleep` timing. (#178)
- **Diff tab button and health pills re-appear after CSP tightening** — the self-hosted-fonts PR (#171) moved `style="display:none"` attributes from HTML to CSS ID rules (`#tab-btn-diff { display: none }` etc.) so the CSP `style-src 'self'` restriction was met. However, the JS that showed those elements used `element.style.display = ''` (empty string), which removes the inline override and lets the CSS `display: none` rule win — keeping them permanently hidden. Fixed by introducing a `.hidden { display: none !important }` utility class in `style.css` and applying it to the 7 affected elements in `index.html`; all `style.display` assignments in `static/render.js` and `static/ws.js` are replaced with `classList.add/remove/toggle('hidden')`. - **Web server transient error no longer panics** — `axum::serve(...).expect("Web server failed")` inside a spawned task would panic the task on any transient I/O error. - **Busy-poll drain loop replaced with event-driven `Notify`** — the graceful shutdown path spun in a 100 ms sleep loop checking `active_connections`. Added `drain_notify: Arc<Notify>` to `MllpStats`; each connection handler calls `notify_one()` when it decrements the counter to zero. `main` now uses `tokio::time::timeout(shutdown_timeout, drain_notify.notified())` — zero CPU during the drain wait, exact wake-up on last connection close. (#115)
- **`MessageStore::search` — zero heap allocation per message per query** — the previous implementation called `.to_lowercase()` on six fields of every stored message on each search request (up to 60 000 short-lived `String`s for a full 10 000-message store). HL7 data is almost always ASCII, so the fast path is taken in practice. (#133)

## [0.4.0] – 2026-03-08 – Message Analysis

> Completes Milestone 3 (Message Analysis). Harux now understands the content of messages: field names from the HL7 v2.5.1 spec, validation with severity-coded badges, a segment diff view, and quick copy-to-clipboard throughout.

### Added
- **HL7 field dictionary** — hover over any field in the detail view for a CSS tooltip with its official HL7 v2.5.1 description (e.g. "Patient Name" for PID-5); powered by a compiled-in zero-overhead JSON dictionary (#48)
- **Message type detection** — detail header shows a human-readable type description (e.g. "Admit / Visit Notification") and a "Typical segments" bar with coloured badges indicating which segments are present vs absent (#45, #50)
- **Segment description tooltips** — hovering a segment header (e.g. `MSH`, `PID`) shows its official HL7 description as a CSS tooltip below the header; the same description appears as a native `title` tooltip on every typical-segment badge (#45)
- **Validation engine** — rule-based validator checks required MSH fields and message-type-specific segments (ADT, ORU, ORM, OML, SIU, MDM); warnings shown as an amber badge in the message list and a collapsible panel in the detail view (#46, #51)
- **Data type validation** — the validation engine checks NM (numeric), DT (date), TS (timestamp), and SI (sequence ID) field values against the HL7 v2.5.1 dictionary; violations appear as blue `INVALID_DATATYPE` badges in the detail view, distinct from missing-field (amber) and missing-segment (red) warnings; only first field component is validated to avoid false positives on composite values (#62)
- **Validation status filter** — header button cycles through All → Warnings Only → Errors Only; also supports `has:warnings` / `has:errors` prefixes in the search bar for combined filtering (#60)
- **Segment diff** — pin any message as a reference with the `◎` button in the list row, then open the Diff tab on another message to see a field-level side-by-side comparison with red/green highlighting (#47, #52)
- **Diff: ignore dynamic fields toggle** — toggle switch in the Diff tab hides MSH-7 (Date/Time) and MSH-10 (Message Control ID) from the comparison; the summary shows how many dynamic fields were hidden so nothing is silently lost (#61)
- **Quick copy to clipboard** — three copy targets in the detail view: (1) segment header shows a 📋 icon on hover that copies the raw segment string; (2) any field value cell is click-to-copy with a green flash feedback; (3) Raw tab has a "📋 Copy All" button that copies the entire message text (#63)
- **Detail header layout** — message title, type description, and meta line are stacked vertically on the left; Bookmark button and tag controls are grouped on the right side of the header

### Fixed
- **ISO 8859/1 Encoding** — implemented two-pass MLLP frame decoding with `encoding_rs` to respect the charset declared in MSH-18 before parsing, preventing corruption of extended Latin characters (#78)

- **Duplicate CSS blocks** — removed redundant `.theme-toggle` styles from `style.css` (#57)
- **Missing ACK styling** — added the missing `.msg-ack` class to center align and correctly style ACK codes (#58)
- **Pin button highlight color** — decoupled pin button styling from bookmarks to ensure pinned items highlight in blue instead of yellow (#59)
- **Diff table column widths** — enforced strict layout on the segment diff table using `table-layout: fixed` so right-hand columns don't stretch (#67)
- **Typical-segment badge colour for data type warnings** — `INVALID_DATATYPE` warnings no longer turn a segment badge yellow; only `MISSING_FIELD` triggers amber, keeping the badge colour semantics accurate (red = missing segment, amber = missing required field, blue = present)

## [0.2.0] – 2026-02-21 – Stabilization & Robustness

> ACK storm prevention, size-based store eviction, UI improvements and error handling for production use with Orchestra/MDM traffic.

---

### Added

#### MLLP Server (Backend)
- Asynchronous TCP listener based on **Tokio** (`rt-multi-thread`)
- Correct MLLP framing: start block `0x0B`, end block `0x1C 0x0D` per the HL7 MLLP standard
- **ACK/NAK generation**: automatic response with `AA` (Application Accept) for valid messages and unknown message types; `AE` (Application Error) for missing or malformed MSH segments
- **ACK storm prevention**: incoming ACK messages are never ACK'd back
- Parallel client connections via `tokio::spawn` per connection
- **DoS hardening**: 10 MB payload limit, connection timeouts
- **Graceful shutdown**: clean termination of active connections on `Ctrl+C` via signal handler

#### HL7 v2.x Parser
- Dynamic delimiter detection from the MSH segment (field separator, component, subcomponent, escape, and repetition separators)
- Extraction of key MSH fields: message type, trigger event, sending/receiving facility & application, message ID, timestamp
- MSH field indices correctly aligned with the HL7 standard (+1 offset)
- PID segment extraction: patient ID (PID-3), patient name (PID-5)
- Robust error handling: parse errors result in a PARSE ERROR marker in the UI rather than a server crash; failed messages are stored in the store
- Structured segment and field representation (`Hl7Message`, `Hl7Segment`, `Hl7Field`, `Delimiters`)

#### In-Memory Message Store
- Central store with `Arc<RwLock<>>` for thread-safe access
- **Dual eviction**: messages are evicted when either the maximum count (`DEFAULT_CAPACITY`) or the maximum byte size (`MAX_STORE_BYTES`) is exceeded — no OOM
- Broadcast channel (`tokio::sync::broadcast`) for real-time notification of all active WebSocket clients on new messages
- Each message receives a unique UUID v4 and an ISO 8601 receive timestamp

#### Web API (Axum)
- `GET /api/messages` — list of all stored messages (paginated, as `Hl7MessageSummary`)
- `GET /api/messages/:id` — full message details including parsed segments and raw HL7
- `GET /api/search` — search endpoint with query parameter `q`
- `GET /api/stats` — live statistics: received messages, parse errors, active connections, MLLP port
- `POST /api/clear` — clear the store
- `GET /ws` — WebSocket endpoint for real-time message push
- CORS middleware for browser access
- Embedded static files via `rust-embed` (no separate web server required)

#### Web UI (Embedded SPA, Vanilla JS)
- **Real-time message list** via WebSocket — new messages appear instantly without page reload
- **Batch rendering** every 250 ms — prevents DOM freezing at high message volumes
- **Pause / Live mode** — button buffers incoming messages; flush and return to live mode
- **Toast notifications** — subtle in-app notifications for relevant events
- **Detail view** with three tabs: `Parsed`, `Raw`, `JSON`
- **Search & Filter** — by message type, patient name, facility, message control ID, source IP; supports `has:warnings`/`has:errors` (#60)
- **Validation Filter** — 3-state toggle in the header to quickly isolate messages with warnings or errors (#60)
- **Bookmark & Tag** — pin important messages (eviction-protected), add custom text tags
- **JSON export** — download individual messages as `.json`
- Dark theme with CSS variables
- PARSE ERROR marker in red for failed messages

#### Build & Deployment
- Single Rust binary, no external runtime dependencies
- **GitHub Actions CI/CD**: three independent build jobs for Windows (`.exe`), macOS Apple Silicon, and Linux on every push to `main`
- Build artifacts are automatically attached to GitHub Releases
- MIT license
- Test scripts: `tests/test.sh` (Linux/macOS, netcat, 100 messages) and `tests/test.ps1` (Windows, .NET TcpClient, 1000 messages, persistent connection)

### Fixed

- MSH field indices aligned with the correct HL7 standard offset (`9ef8ed9`)
- Route for the message detail view corrected from `{id}` to `:id` (correct Axum syntax) (`f33ccfc`)
- Compiler warnings (`dead_code`, `unused_variables`) cleaned up (`f33ccfc`)
- ACK storm prevention: incoming ACK messages are detected and never ACK'd back (`041cb04`)
